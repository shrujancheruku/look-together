# An Inquiry is an app-owned state machine; the model only proposes moves

The app, not the model, holds an Inquiry's state and its Assumptions as records on the device. Each model call returns its reply with structured events (pick an Assumption, try an angle, reword or reject a premise, record a challenge with the person's own words, leave an Open Question), and one shared reducer checks each event against the rules before applying it. We chose this over one long conversation in which the model keeps the Assumptions, counts the angles and decides when to give the Recap, because the hard lines (at most 3 angles, a Step-out that never resumes, quotes that are really the person's words, a Recap built from what actually happened) would then only be promises the prompt makes, and could break silently with every model switch. We chose it over an app that runs a fixed prompt for every step because only the model can tell from the conversation when the person is stuck or has moved to another Assumption. The records and what the person hears must never disagree: when the rules refuse an event that would have changed the state, the reply is held back and the model is called once more, and in voice the device saves each new Inquiry before the app speaks the reply. The cost is a structured output contract that every prompt and every future model must keep, checked by the evaluation set.
