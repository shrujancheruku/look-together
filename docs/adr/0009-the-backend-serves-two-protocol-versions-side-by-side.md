# The backend serves the current and previous protocol version side by side

One **protocol version** covers everything the device and the stateless backend must agree on for an Inquiry: its stored `schemaVersion`, the event set and the reducer's rules ([ADR 0004](0004-inquiry-is-an-app-owned-state-machine.md)). The device sends it on every `POST /turn`, and the backend keeps the reducer and prompt set for both the current version and the one before it, picking one based on the version each request declares. We chose this over accepting only the latest version because store builds get no over-the-air updates, so forcing every update would block people mid-Inquiry with every release. We chose it over upgrading old Inquiries on the server and downgrading the replies because that needs migrations that run backwards and a second copy of every rule to keep in sync. Migrations stay forward-only and run on the device, on stored records and on imported files alike, so the backend only ever sees a version the app itself writes. The previous version is retired once it falls below about 2% of turns or 90 days after the new one reaches both stores, whichever comes later, or at once by a deploy with a stated reason if it breaks a hard line. Below the window only new turns are blocked: the person sees an update screen, and reading, export, delete and Help keep working. The cost is two reducers and two prompt sets live at once, each needing its own gate-tier pass record, and a fixed release order: backend in both regions, then web, then store builds.
