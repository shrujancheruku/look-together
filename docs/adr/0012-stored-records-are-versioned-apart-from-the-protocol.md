# Stored records are versioned apart from the protocol

The device versions what it stores and what it sends separately. The **protocol version** `v` covers only what the backend sees: the turn request and response, the model's output schemas, the event set and `check`, the limits the backend enforces, and `prompts/vN`. Each `v` is a frozen `vN/` folder, and the gate keys on it. The **record version** (`schemaVersion`) covers the stored Inquiry: its shape, the device's own `step` inputs (`begin`, `pick`, `pause`, `resume`, `finish`, `expire`) and how they're applied, `load`, `pickCopy` and the forward migrations. Each is a frozen `records/rN/` folder that only the device bundles. A change the backend never sees bumps only the record version; it needs no second reducer on the backend, no second prompt set and no second gate pass. A property test in each app build pins the current record version against the current protocol version (`step` is `check(turnContext(inquiry), …)` then apply). Both versions freeze at the first `preview` build (TestFlight external or the Play closed track), since from then on beta testers keep Inquiries on their phones; before it, `v1` and `r1` change in place, with no migrations. We chose this over one version for both because ADR 0009's cost of two live reducers, two prompt sets and two gate records would then be paid for storage changes the stateless backend never reads. We chose it over splitting later because a split after launch would have to migrate both meanings at once. The cost: two numbers to keep straight, and a migration chain per record version beside the protocol's N and N-1 window.
